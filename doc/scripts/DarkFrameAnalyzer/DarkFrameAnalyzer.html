1 Description

[hide]

Version française de cette documentation

A master dark is a statistical combination of a series of individual darks.It assumes that all the frames of the series describe the same sensor, at thesame temperature, with the same exposure time and the same read conditions. Asingle frame that breaks this assumption, because the cooling had not settled,because a light leak reached the sensor, or because the camera returned acorrupt frame, degrades the master dark that every light frame is thencalibrated with.

Dark Frame Analyzer measures each frame of a series and compares it with theseries itself. For every dark it computes a sigma-clipped median, an exactmedian absolute deviation derived from the 16-bit histogram, the number of hotand saturated pixels, the deviation between the temperature setpoint and thesensor temperature read from the FITS header, and the gradient between thecenter of the frame and its corners. It then classifies every frame as valid,as an alert, or as rejected, and reports both a color-coded table and adetailed console report.

The script reads the frames, and never modifies them. It writes nothing unlessyou ask for it: see Privacy, network and files below.

2 Usage

[hide]

The script is available from the Script > CaeloWorks > DarkFrameAnalyzermenu item.

2.1 Adding dark frames

Darks opens a file dialog to select individual frames, and Directoryadds every dark found in a directory. FITS (.fits, .fit, .fts) andXISF (.xisf) frames are accepted, in uppercase or lowercase. Removedrops the selected rows and Clear all empties the list.

All the frames of one series should be added at once: the statistical part ofthe detection compares each frame with the others, so a list that mixes twodifferent series, or two temperatures, produces meaningless alerts.

2.2 Detection thresholds

The Detection thresholds panel holds two kinds of criterion, and bothare applied to every frame.

  • Absolute criteria compare a frame with a fixed value: the maximumdeviation between the temperature setpoint and the sensor temperature, indegrees Celsius; the ADU level above which a pixel counts as hot; the maximumnumber of saturated pixels tolerated per frame; and the maximum gradient, inADU, between the center and the corners of the frame. They do not depend onthe rest of the series.
  • Statistical criteria compare a frame with its series: a sensitivityin sigma units for the median, the noise, the hot pixel count and theuniformity, plus the absolute deviations, in ADU, above which a deviation ofthe median or of the noise becomes an alert or a rejection. They need at leastthree readable frames; below that, the script reports that the statisticaldetection has been skipped, and applies the absolute criteria only.

The thresholds persist across sessions. Defaults restores the valuescalibrated for IMX585-class sensors that the script ships with.

2.3 Running the analysis

Analyze measures every frame of the list. The interface is locked while theanalysis runs, and Cancel interrupts it: the frames already measured arekept, and the console reports how many frames were processed out of the total.

A row marked Alert deviates from the series without being unusable: look atit, and decide. A row marked Rejected should be kept out of theintegration. Clicking a column header sorts the table; the Temp. andΔ corn. columns are sorted as text, because they carry a sign, souse the CSV export when the order of those two columns matters.

2.5 Console report

The console receives a table of the per-frame metrics, the reference valuescomputed for the series, the reason why each frame has been flagged, and asummary of the valid, alerted and rejected frames. It is the complete recordof the analysis, and it can be copied out of PixInsight as plain text.

2.6 CSV export

Export CSV... writes every metric of the last analysis to a CSV file,at the location you choose in a save dialog. The headers are fixed Englishidentifiers, whatever the language of the interface, so that the file can beread by other tools.

2.7 WBPP exclusions

WBPP exclusions... opens the list of the frames that should be kept outof the integration: the rejected frames, and also the alerted ones whenInclude alerts is checked. From that dialog, Export .txt...writes the list to a text file, one path per line, at a location you choose,and Move to rejected/... moves the listed frames to a rejectedsubdirectory created next to them, so that WBPP no longer sees them. The moveasks for a confirmation first, and the frames are moved, never deleted.

2.8 Interface language

The interface is available in English and French, selected from the languagelist of the dialog. The choice persists across sessions. The headers of theCSV export are unaffected.

3 Privacy, network and files

[hide]

3.1 Network

The script makes no network connection of its own. It downloads nothing,uploads nothing, and contains no telemetry: nothing is measured, counted ortransmitted about you or about your frames.

One action involves the network, and only when you ask for it: clicking theby CaeloWorks line in the header of the dialog opens the page of thisscript on the developer website, atpixinsight-scripts.caelo.works, in the web browser configured on yoursystem. The full URL is shown in the tooltip of that line before you click it,and follows the language of the interface.

3.2 External programs

To open that page, and only then, the script asks your operating system toopen the URL with your default web browser. It runs cmd /c start onWindows, /usr/bin/open on macOS and xdg-open on Linux, with the URL asits only argument. No other program is ever launched, no program isdistributed with the script, and nothing is launched without an explicit clickfrom you.

3.3 Files written outside the PixInsight installation

The script never writes inside the PixInsight installation, and never modifiesyour dark frames. Outside the installation it writes only on an explicitaction, and only where you tell it to:

  • The CSV report of the analysis, at the path selected in the savedialog of Export CSV... .
  • The exclusion list , a .txt file, at the path selected in the savedialog of the WBPP exclusions... dialog.
  • A rejected subdirectory next to the frames to exclude, created byMove to rejected/... in that same dialog, after a confirmation.The rejected frames are moved into it; no file is deleted.

3.4 Settings

The detection thresholds and the language of the interface are stored throughthe settings interface of PixInsight, under the DarkFrameAnalyzer key ofthe settings of the application. The script reads and writes nothing elsethere, and touches no setting belonging to PixInsight or to another product.

4 Requirements and limitations

[hide]

  • PixInsight 1.9.0 or newer, on Windows, macOS and Linux.
  • FITS (.fits, .fit, .fts) and XISF (.xisf) dark frames.
  • The sensor temperature and the setpoint are read from the FITS header. Aframe whose header carries neither cannot be checked for thermal drift.
  • The statistical criteria need at least three readable frames. With fewer,the script says so explicitly and applies the absolute criteria only.
  • The Temp. and Δ corn. columns of the table are sorted astext, because no readable form of a signed number sorts correctly as text in aPixInsight tree box. Use the CSV export to order a series on those twometrics.
